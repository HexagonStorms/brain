Polaris runs Claude Code inside WSL2 Ubuntu (Linux user `josh`, home `/home/josh`), separate from the native Windows install reached by `ssh polaris`. There is no sshd listening on that WSL instance itself (it shows up as its own Tailscale node, `polaris-ssh` / 100.89.161.6, but port 22 is closed there) — the only way in is `ssh polaris` (native Windows, PowerShell) then `wsl -d Ubuntu -u josh -- <cmd>` from there. Non-interactive `bash -c` invocations don't source `.bashrc`, so `claude` isn't on PATH; call the versioned binary directly or use `bash -lc`.

**headroom**: a local Anthropic-API proxy Jo runs on that box (pipx install, `~/.local/share/pipx/venvs/headroom-ai`, binary `~/.local/bin/headroom`, `headroom.cli proxy --port 8787 --mode token --backend anthropic`). It does per-request token accounting. Its Claude Code plugin (`headroom@headroom-marketplace`) forces `ANTHROPIC_BASE_URL=http://127.0.0.1:8787` in `~/.claude/settings.local.json` and re-asserts itself via `SessionStart`/`PreToolUse` hooks (`headroom init hook ensure`). This config has been stable since 2026-06-15.

**The regression:** Claude Code auto-updated on this box from 2.1.218 to 2.1.219 at 2026-07-24 10:19 local time. `/rc` and `/remote-control` disappeared entirely (not an error, just absent from the command list) immediately after, with no other config change. 2.1.219 apparently tightened detection of gateway/third-party-provider deployments (any non-default `ANTHROPIC_BASE_URL`) and hides Remote Control under it — matching the documented behavior "Fixed /remote-control appearing for gateway and third-party provider deployments where it cannot function," and a long-running GitHub thread (anthropics/claude-code#29796, closed as stale/duplicate but recurring release after release) of `/rc`/`/remote-control` vanishing after updates in gateway-proxy setups. Elowynn runs the same 2.1.219 with no `ANTHROPIC_BASE_URL` override and `/rc` works fine there — the trigger is the combination of 2.1.219 + a custom base URL, not the version alone.

**Fix applied 2026-07-24:** `~/.local/bin/claude` is a plain symlink to a versioned binary under `~/.local/share/claude/versions/`. Repointed it from `2.1.219` back to `2.1.218` (`ln -sfn ~/.local/share/claude/versions/2.1.218 ~/.local/bin/claude`) to restore the last known-working version without touching headroom. This is a manual symlink swap, not an official version pin — Claude Code's own auto-updater may silently flip it back to latest on a future launch (this box's `~/.claude.json` shows `autoUpdates: false`, but a real update still landed at 10:19 that same morning, so that flag alone did not prevent it). If `/rc` disappears again after relaunching Claude Code on Polaris/WSL, check `~/.local/bin/claude` first before re-diagnosing from scratch.

**How to apply:** Don't assume a missing built-in command is an account/org-policy issue (see [[reference_claude_dual_accounts]] for that separate, real but different cause on the native-Windows work-account login) before checking (a) whether `ANTHROPIC_BASE_URL` or another gateway override is set for that session, and (b) whether the Claude Code version just changed. Compare `~/.claude.json` `cachedGrowthBookFeatures`/version fields and the `versions/` directory mtimes across machines before theorizing further.
